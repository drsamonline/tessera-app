One customer. Four systems. One record you can prove.

Your CRM, helpdesk, ERP and inbox each hold a slice of the same customer, and they disagree. TESSERA merges them field by field, shows where every value came from, and records the whole thing in a hash chain you can verify in your own browser.

What it actually does

Not a dashboard over a spreadsheet. Every screen is a decision you can act on, and every action is recorded.

01 · merge

Field-level, not record-level

Email comes from HubSpot because it owns it. The deal amount comes from NetSuite because it owns that. A field nobody owns falls back to trust, then to you.

02 · resolve

The rule is shown before the answer

Every disagreement names the rule that decides it — authority map, trust score, or human review — so you are approving a mechanism, not guessing at one.

03 · prove

The ledger verifies in your browser

Each event is SHA-256 hashed against the one before it. Press verify and the page recomputes the chain locally. Alter one event and it fails at that sequence number.

04 · route

Work goes to a position

Tasks are assigned to seats, not people. A human or an agent fills the seat, and the router shows its term-by-term arithmetic for why it picked the one it did.

05 · approve

Agent playbooks are proposals

A workflow authored by an agent cannot run until a person approves it. The button says Approve first and it is disabled, because that is what the rule is.

06 · offline

Nothing leaves the device

No network calls after first load. State lives in localStorage, the service worker caches the shell, and the ledger is rebuilt locally if you clear it.

What this is not

The same honesty the engine repository runs on.

Not connected to your systems

This console runs on seeded data. The real connectors exist in the engine and have never touched a live tenant — that gap is documented, not glossed.

Not a backend

There is no server, no database and no auth here. It is a demonstration of the logic, installable and offline, so you can judge the behaviour before reading the specification.

Not audited

The hashing is Web Crypto. The key handling in the engine is a reference construction and says so. Nothing here should hold real customer data.

Run it

Three ways, none of which need a build step.

# 1. in place
open app/index.html

# 2. any static server
python3 -m http.server 8000     # then /app/

# 3. install it
# open /app/ in Chrome or Edge, then "Install TESSERA" from the address bar

For a desktop binary, wrap the folder with Tauri or Electron — the app is a static page, so either takes minutes. For Android, a Trusted Web Activity over the hosted URL gives a real APK from the same files. Both paths are written up in BUILDING.md.
