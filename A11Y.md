# Accessibility

A hand audit, run against the real app in a real browser. Not a claim of WCAG conformance — a record of what was
measured, what failed, and what has not been tested at all.

**Method.** `tests/a11y-harness.html` loads `index.html` in a same-origin iframe, waits for the boot to settle, then
runs eight checks and writes the result into its own DOM. Run it by serving the directory and opening that page.
Chromium, 14 November 2026.

## The eight checks

| Check | Result |
|---|---|
| Every interactive control has an accessible name | **50/50** |
| The command palette opens from `#command` | pass |
| The palette's focus trap holds under Tab | **25/25 tabs stayed inside** |
| Escape closes the palette | pass |
| The ledger table has real `<th>` headers | 4 |
| One visible `h1`, no heading-level skips | `[1]`, no skips |
| No positive `tabindex` | 0 |
| A `prefers-reduced-motion` block exists | pass |

## The one failure, and the fix

An outlined button on a card had a `1px` border at **1.34:1** against that card. WCAG 1.4.11 asks for 3:1 on the
boundary that identifies an interactive control, and a button whose only boundary is a 1.34:1 line is a button you
cannot see.

The fix is a second token rather than a global change: `--line` stays quiet for decorative borders — cards, dividers,
table rows — and `--line-control` (`#6b7480` dark, `#8a8378` light) is applied to every interactive boundary:
buttons, inputs, selects, the segmented control, the palette field and the import textarea.

Measured after: **3.28:1 dark, 3.42:1 light**. Above the floor, still below the text tokens, which is the right
relationship — a border should not compete with a label.

## What this audit did not test

- **No screen reader.** Nothing here says how NVDA, VoiceOver or TalkBack reads the app. The accessible-name check
  proves a name exists, not that it is a good name.
- **No 400% reflow.** WCAG 1.4.10 needs content to work at 320 CSS pixels wide without two-dimensional scrolling. The
  app is laid out for 390 and 1440; the middle was not measured.
- **No axe or equivalent.** The checks are hand-written, so they test what I thought to test.
- **Reduced motion was checked for existence, not behaviour** — the block is present and the transitions are named
  there; whether every animation honours it was not traced.
- **The toast is `aria-live="polite"` but was not verified with a reader.** An undo that appears and disappears in
  nine seconds may be announced too late to act on. That is a design risk, not a code defect, and it is unresolved.

## The honest summary

The app is keyboard-complete and its text meets AA in both themes. Its control boundaries now meet 1.4.11. It has
never been used by a person with a screen reader, and until it has, "accessible" is a claim about markup rather than
about people.
